🌱 Potager de Poche

Un cadeau pour ceux qui n'ont pas de jardin.

Par Adrien · fait en 3 semaines avec Tripo et une équipe d'IA

Au départ

Un Tamagotchi de balcon.

Mon idée de base : un personnage qui vit tout seul sur son balcon et qui cultive. On vient le voir, on plante, on attend, on vend.

J'avais déjà 3 personnages en tête, et l'habitude de travailler avec plusieurs IA.

26 septembre · je commence

Le thème du Tripothon : « Un cadeau pour ______ ».

1
Je choisis : un cadeau pour ceux qui n'ont pas de jardin.
2
Le thème se voit dans la 3D : toits de zinc, rambardes, pots serrés — un vrai balcon de Paris.
3
Le nom : « Jardin de poche » devient « Potager de Poche » — on cultive pour manger.
4
Soumis le 5 octobre. Depuis, j'ai continué : tout ce que vous voyez aujourd'hui est la version du jour.

27 septembre · l'idée évolue

« Planter, attendre, vendre » : trop plat.

Cultiver→Manquer→Troquer→Cuisiner→Offrir

Pas d'argent : des points, gagnés en offrant un plat. Ils achètent les graines et les pots, et rendent les trocs équitables.

Une recette du jour à laquelle il manque toujours un ingrédient → on a besoin des voisins. Chaque balcon a ses graines interdites, racontées par le décor.

Jimy

Chapitre

Tripo

Mes personnages et mes plantes viennent de Tripo.

Tripo · les personnages

1
Je pars d'images de chaque personnage : Tripo les transforme en 3D (image → 3D), puis Tripo Texturing pour les couleurs.
2
Dans Blender, je prépare le corps pour Mixamo : squelette X Bot, même pour les trois.
3
J'ai changé de personnages en cours de route : tout refaire, mais le squelette commun a sauvé les animations.

Tripo · les plantes, avec Codex

25 plantes × 7 stades, générées par Codex via l'API Tripo.

1
Je demande à Codex de vérifier d'abord si c'est possible et de me rendre un rapport : méthode, coût en crédits, risques.
2
Test sur la tomate, puis la fraise : Codex fabrique une planche (les 7 stades sur une image), un seul passage Tripo, séparation dans Blender.
3
Jamais de génération sans mon ok : essai à blanc, contrôle des crédits, autorisation, puis seulement la dépense.
4
Un script Blender (écrit par Codex) découpe chaque planche en 7 objets, les renomme et les range par plante : 25 familles, 175 objets, avec une grille de contrôle. Stades manquants, feuillages collés → corrigés un par un.
5
Pour le téléphone : 38,97 Mo → 8,06 Mo (626 964 triangles, Draco, textures réduites).

Tripo · l'Atelier, en direct aujourd'hui

Les visiteurs créent leur objet.

Code QR→Description ou photo→Aide de l'IA→Tripo Ultra→Sur le balcon

L'objet est compressé par le serveur, visible en 3D dans le téléphone, et posé en hauteur sur un mât Tripo au coin du balcon.

Tripo · une IA pour écrire la description

✨ « Améliorer ma description »

1
Le visiteur écrit trois mots dans sa langue : « un chat qui dort ».
2
Une IA (Cerebras, sinon Gemini) propose une description complète : sujet, détails, matière, style, qualité.
3
Il la relit, la modifie s'il veut, et confirme. La version anglaise part à Tripo.
4
Résultat : des objets bien plus beaux, pour les mêmes crédits. Et Tripo garde sa propre modération.

Chapitre

Blender : le décor, à la main.

L'immeuble, les balcons, les mesures.

Blender · ce que j'ai fait moi-même

  • L'immeuble et les trois balcons : faits dans Blender, avec des scripts Python.
  • Les objets de déco : par Tripo et par Codex.
  • Des scripts Python pour exporter, cuire les textures, vérifier le placement des meubles, réparer les squelettes.

Blender · la vraie galère : les obstacles

Il a fallu connaître chaque taille, chaque emplacement.

  • Le personnage doit marcher entre les pots, s'asseoir au bon endroit, prendre l'arrosoir dans la main.
  • Mesures de chaque meuble, de chaque squelette, de chaque main → fichiers de mesures et de placement par balcon.
  • Un panneau de réglage en direct (?tune=1) pour caler l'arrosoir, la caméra, les pieds.
  • À chaque changement de personnage ou de plante : tout remesurer.

Mixamo · les animations

  • Squelette X Bot + bibliothèque d'animations partagée par les trois corps.
  • Marcher, semer, arroser, récolter, s'asseoir, danser, dormir, cuisiner.
  • Galère : les animations ne collaient pas aux trois morphologies → mesures, réglages, demi-tours, prises d'objets, interruptions. Plusieurs passes.
  • Le bras de Marcel figé : la peau accrochée à l'épaule → script Blender qui la rend au bon os.

Mes règles

  • Une chose à la fois. Chaque changement est testé, puis mis en ligne seul.
  • Les IA ne publient jamais. Rapport d'abord, mon ok, puis je pousse moi-même.
  • Toujours pouvoir revenir en arrière : étiquette Git avant chaque mise en ligne, copies datées, retour en une commande.
  • Ne rien inventer : ni mécanique, ni texte, ni chiffre.

Chapitre

La sécurité.

Codes à usage unique, secrets côté serveur.

Sécurité · les codes

  • Chaque objet Tripo coûte des crédits : on ne crée qu'avec un code à usage unique.
  • Le code est brûlé au moment de la création, et rendu si Tripo refuse.
  • Je distribue les codes par QR code depuis mon tableau de bord. Sans code valide, rien n'est généré.

Sécurité · les secrets

  • Les clés (Tripo, Supabase, Gemini, Cerebras) ne sont que sur le serveur : le navigateur ne les voit jamais.
  • Les tables sont fermées ; seules des fonctions contrôlées y écrivent.
  • Les mots de passe sont chiffrés par Supabase : personne n'y a accès, même pas moi.
  • Pas de chat libre entre joueurs ; anti-robot à la création de compte.

Chapitre

Ce que je prépare.

Pas des idées : des chaînes qui existent déjà.

La suite · ton personnage jouable

Même circuit que l'Atelier, plus le squelette.

1
Tu l'achètes dans le jeu : tu le décris ou tu envoies une photo → Tripo le fabrique.
2
Tripo Rig Check (gratuit) vérifie que c'est un bipède, puis Tripo Auto Rig pose le squelette avec les os nommés comme Mixamo (option « spec : mixamo », 25 crédits).
3
Mon jeu partage déjà une bibliothèque Mixamo entre Léa, Marcel et Jimy : le nouveau perso utilise les mêmes animations, sans rien refaire.
4
Secours : Tripo Retarget (100+ animations préréglées) si une animation manque.

La suite · les vrais joueurs entre eux

Offrir, puis troquer, pour de vrai.

1
Les comptes existent déjà (Supabase) : les vrais joueurs apparaissent en haut de la liste des voisins, les voisins simulés restent pour que le jeu vive tous les jours.
2
Offrir : je choisis un plat ou une récolte, un voisin, et c'est une fonction du serveur qui le retire chez moi et l'ajoute chez lui, en une seule transaction (comme les codes de l'Atelier).
3
Troquer : je propose « 2 tomates contre 1 basilic » ; l'autre voit l'offre dans son téléphone, accepte ou refuse ; l'échange se fait au moment de l'acceptation, jamais à moitié.
4
Pas de chat libre : des messages préfaits. Plus tard, des immeubles qui regroupent des joueurs aux besoins complémentaires.
